Building the wheel and docs
===========================

Wheel
-----

``scripts/build_wheel.py`` builds and verifies a distributable wheel. It uses
PEP 517 via the ``build`` package when available, falls back to
``pip wheel --no-build-isolation`` offline, and inspects the archive before
declaring success. With ``--sdist`` it also writes a source distribution;
when ``build`` is missing, setuptools' backend produces it directly.

.. code-block:: console

   $ python scripts/build_wheel.py                 # dist/*.whl
   $ python scripts/build_wheel.py --clean         # remove build/ and dist/
   $ python scripts/build_wheel.py --sdist         # wheel + sdist
   $ python scripts/build_wheel.py --check         # inspect newest wheel
   $ python scripts/build_wheel.py --out wheels    # custom output dir

Options
~~~~~~~

``--clean``
   Remove ``build/``, ``dist/`` and ``*.egg-info`` first.
``--sdist``
   Also produce ``dist/netease_api_recovered-<version>.tar.gz`` (wheel +
   source). Works offline: without the ``build`` package the script calls
   setuptools' PEP 517 backend itself.
``--no-isolation``
   Build without an isolated environment, useful offline. The script also
   retries with this automatically if an isolated build fails.
``--check``
   Skip building and only validate the newest wheel.

The verification step checks that the wheel contains the package entry points
(``netease_api/__init__.py``, ``client.py``, ``routes.py``, ``cli.py``,
``transport.py``, ``crypto.py``, ``errors.py``, ``apis/__init__.py``), that it
does not contain ``tests/``, ``tools/``, ``examples/``, ``extracted/``,
``docs/``, ``.apk``, ``.dex`` or ``.so`` files, and it prints the metadata,
member count, SHA-256 and size. The source distribution is checked too: it
must contain the package, docs, tests, scripts and metadata, and
must not contain caches, ``cookies.txt``, APK/DEX files or the old archives.

Install the result with:

.. code-block:: console

   $ pip install dist/netease_api_recovered-1.0.0-py3-none-any.whl

Sphinx documentation
--------------------

Install the docs dependency and build HTML:

.. code-block:: console

   $ pip install -r docs/requirements.txt
   $ python -m sphinx -b html docs docs/_build/html

On Windows, ``docs\make.bat html`` does the same; POSIX users can run
``make -C docs html``. The output is in ``docs/_build/html/index.html``.

To check for warnings (the docs build should be warning-free):

.. code-block:: console

   $ python -m sphinx -b html -W --keep-going docs docs/_build/html

The API reference is generated with ``sphinx.ext.autodoc`` from the package
docstrings, so it stays in sync with the code. The full route catalog page
(``docs/route_catalog.rst``) is generated by ``tools/gen_docs.py`` together
with ``ROUTES.md``:

.. code-block:: console

   $ python -I tools/gen_docs.py

Regenerate it after running the extraction pipeline described in ``API.md``.
